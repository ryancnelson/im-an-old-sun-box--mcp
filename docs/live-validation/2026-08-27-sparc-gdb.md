# Live SPARC GDB validation

SUN-002 was validated on 2026-08-27 against a running Niagara VM on the Linux
VM host.

The installed wheel discovered the live run through its configured root and
proved that the PID command line referenced that exact run. QMP
`query-status` reported `running` before capture. The debugger used
`gdb-multiarch` 15.1, explicit `sparc:v9` architecture, big-endian mode, and
the run's preconfigured private Unix GDB socket.

The 61 ms batch returned the SPARC register set, `pc` and `npc`, sixteen
instructions at the program counter, and a best-effort backtrace. GDB exited
zero and reported the inferior detached. The cleanup path issued `cont`; its
post-capture QMP check and a separate `qemu.status` call both reported
`running`. The QEMU PID remained alive.

GDB warned that it rejected QEMU's target-supplied architecture description.
The explicit profile still produced coherent SPARC v9 registers and
instructions. Keep the warning visible in captures until the target-description
mismatch is understood; do not treat it as capture failure without contrary
evidence.

## Codex CLI end-to-end check

The wheel and host-local configuration were installed on the VM host. A fresh
Codex CLI 0.150.1 process loaded the MCP directly over stdio. Without using a
shell tool, the agent called `lab.list_runs` and `qemu.status`, found the live
run, proved PID identity, and received a typed QMP `running` response with no
warnings or errors.

A second smoke test from Codex on another machine launched the same MCP through
an SSH stdio transport and produced the same read-only result. Guest networking
was not involved in either path.
